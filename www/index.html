The API behind send.sgit.ai, as files a page pins

Everything send.sgit.ai does in the browser lives here: encrypting a file, keeping its name inside the ciphertext, uploading it as one transfer or committing it into a vault, turning the link into a QR code, and remembering the keys on the device. It is published at a versioned address, /v0.1.1/, that is never edited once it is on the default branch, with a manifest of the SHA-256 of every file. Any page, on any site, can import it.

<script type="module">
  import * as send from 'https://api.send.sgit.ai/v0.1.1/send/send-api.js'
  const api = new send.SendTransfers({ endpoint: 'https://send.sgraph.ai', accessToken })
  const r   = await api.send({ bytes, filename: 'report.pdf' })
  const url = send.link.transferLink({ openUrl: 'https://send.sgit.ai/open/', transferId: r.transferId, key: r.keyString })
  document.querySelector('#qr').innerHTML = send.qr.toSvg(url)
</script>

What it is, in one table

An API with no server"API" here means client-side: the modules, formats and contracts a browser runs. This host serves files over GitHub Pages and receives nothing. The server the modules talk to is the SG/Send API at send.sgraph.ai, or any host that serves the same routes, including the one in memory that the tests use
One release, one directory/v0.1.1/ holds send/ (the modules), vendor/ (the vault library and the QR encoder, unchanged and hashed), tests/ (co-located, runnable with Node and in a browser) and manifest.json. Nothing in it loads from another release or another host
Pinned by addressA consuming site names one release in a file, copies its manifest, and loads the code by its full address. Its own gate can then refuse a reference that is not pinned or not in the manifest
Compatible with send.sgraph.aiThe ciphertext layout, the SGMETA envelope, the friendly-token derivations and the link fragments are the ones send.sgraph.ai has shipped since its v0.2.x, so a transfer made here opens there and the other way round. Proved against the published contracts and the in-memory server; a round trip against the live host is still to run, and the reality file says so
Tests that run against real things43 tests in Node against an in-memory implementation of the API, including real vaults made with the vendored library, two clients racing a publish, and the lazy-folder trap. No mocks

Where it sits in the estate

send.sgit.ai is the product: the pages, the examples, the articles and the commercial model. This host is the code they run, kept apart so it has releases of its own, a review boundary, and a way for a second site (or an agent, or a workflow) to say exactly which version it means. The same shape as api.newsroom.sgit.ai for the newsroom, and the pattern is written up in the first article. The brief it all started from is published in full, with its corrections beside it.
